How subscription pricing is estimated

Subscription costs are modeled by applying each selected plan's monthly fee and estimated allowance to the matching provider's API cost. This assumes the allowance is fully used over a long window. It is a comparison estimate, not a provider invoice, and actual limits and usage may differ.

How to read this chart

The X axis shows the cost to run one task of the Artificial Analysis Intelligence Index test suite. The scale is logarithmic: each step to the right multiplies the effective cost by ten. Subscription prices are estimates assuming you fully drain the allowance over a long window, not provider invoices.

The Y axis shows one of six scores. Use the buttons in the filter row to pick one. A higher value is better on all of them.

  • Intelligence — the Artificial Analysis Intelligence Index, a mix of many benchmarks.
  • Coding (SciCode) — the SciCode benchmark score, scaled from 0 to 100. This project uses SciCode because the models feed no longer supplies the former Coding Index. The scores are not comparable to that index. Only models with SciCode scores appear.
  • Math (AIME 2025) — the score on the AIME 2025 math contest, from 0 to 100. Artificial Analysis removed its old Math Index, so this contest score is the stand-in. Only some models have it, so this view shows fewer points.
  • Terminal-Bench v4.0 — the terminal task benchmark score, scaled from 0 to 100. Only models with scores appear. The cost axis and response time filter still use the existing Intelligence Index task costs and response-time measurements, not Terminal-Bench task costs or durations.
  • LiveBench Coding and Agentic Coding use the official LiveBench release 2026_06_25, on a 0–100 scale. Coding averages code generation and completion; Agentic Coding averages JavaScript, TypeScript, and Python evaluations. Missing subtasks are skipped; score details show how many were completed. Only reviewed model-and-effort matches appear. The cost axis uses AA Intelligence Index task costs with the selected subscription adjustment, and the time filter uses AA response times, not LiveBench costs or durations.

The blue line is the Pareto line. A model is on this line when no other shown model is both smarter and cheaper. These models give you the best value for money.

The response time filter

Reasoning models can think for a long time before they answer. The "Max response time" slider hides slow models. The value is the median end-to-end response time in seconds. This is the total time from the request to the last token of a 500-token answer. When you move the slider, the Pareto line is computed again from the models that remain.

Point at a model to see its details. Use the Tab key to step through the models with the keyboard.
